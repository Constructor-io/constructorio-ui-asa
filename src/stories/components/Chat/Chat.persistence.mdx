# Persistent Chat

By default a conversation lives only in memory and is lost on page load. Enable `persistConversation` on `CioAsaProvider` and the transcript plus the agent's thread id are kept in the browser, so a shopper who navigates between product pages or reloads continues where they left off. A signed-in shopper (one with a `userId`) also comes back to it later and in other tabs; a guest's conversation ends with the tab.

```jsx
<CioAsaProvider apiKey="YOUR_API_KEY" persistConversation>
  <Chat />
</CioAsaProvider>
```

## Public API

Everything below is optional and only active when `persistConversation` is set on the provider.

<Markdown>
{`
| Where | Name | What it does |
|-------|------|--------------|
| \`CioAsaProvider\` prop | \`persistConversation\` | \`true\` keeps conversations in the browser: in \`localStorage\` for a signed-in shopper, in \`sessionStorage\` for a guest |
| \`CioAsaProvider\` prop | \`userId\` | Whose conversation this is. Pass the signed-in shopper's id on login, \`null\` (or nothing) on logout. See [Login and logout](#login-and-logout) |
| function | \`clearPersistedConversations({ apiKey, domain, userId })\` | Deletes every stored conversation of that shopper (or of the guest without \`userId\`) in this and every other tab. Optional, for a logout that must leave nothing behind |
| \`Chat\` prop | \`onThreadsChange(threads, activeThreadId)\` | Fires after the initial load and whenever the stored list or the active conversation changes, including changes made in another tab. Use it to render a history list outside \`Chat\` |
| \`Chat\` prop | \`initialThreadId\` | Restores that thread's stored transcript instead of the most recent one; falls back to seeding the thread id alone when nothing is stored |
| \`Chat\` ref | \`newThread()\` | Opens an empty conversation and keeps the current one in storage |
| \`Chat\` ref | \`switchThread(threadId)\` | Loads a stored conversation and continues it on the same agent thread |
| \`Chat\` ref | \`clearHistory()\` | Resets the conversation and deletes it from storage |
| \`useAsaResults\` | \`isHydrating\` | \`true\` while a stored conversation is being restored |
| \`useAsaResults\` | \`threads\`, \`activeThreadId\` | Stored conversations, most recent first, and the id of the one on screen (\`null\` for an unsaved one) |
| \`useAsaResults\` | \`newThread()\`, \`switchThread(threadId)\` | Same as the \`Chat\` ref methods, for custom UIs |
`}
</Markdown>

`ThreadSummary` carries `threadId`, `title` (the first question), `createdAt`, `updatedAt` and `inFlight`, which is `true` while the latest answer of that thread is still streaming.

## Login and logout

History is stored per shopper, and the shopper is whoever `userId` says. Set it on login, remove it (or pass `null`) on logout. Everything else follows from that. On login the conversation on screen, if any, is carried over into the shopper's history and continues without interruption, even mid-answer; the guest copy is removed. When one signed-in id is replaced by another, or on logout, the chat switches storage, clears the screen and loads that shopper's own history, never reading a key that belongs to another id. This holds in every open tab. Use the same id you give Constructor for personalization, stable for that person over time and not an email or anything personal, because it becomes part of a `localStorage` key that any script on the page can read.

```jsx
<CioAsaProvider apiKey="YOUR_API_KEY" persistConversation userId={user?.id ?? null}>
  <Chat />
</CioAsaProvider>
```

With `apiKey` the id is also set on the client the provider builds, so agent requests and stored chats agree. With your own `cioClient`, set `userId` on the client as well; a mismatch is reported in development.

By default nothing is deleted on logout. The history stays on the device under the old id for 7 days and comes back if the same shopper signs in again there. It cannot be shown to anyone else through the chat, but it is plain data in `localStorage`, readable from DevTools and by other scripts on the page. When that is not acceptable, delete it on logout:

```js
import { clearPersistedConversations } from '@constructor-io/constructorio-ui-asa';

function onLogout(user) {
  clearPersistedConversations({ apiKey: 'YOUR_API_KEY', domain: 'chatbot', userId: user.id });
}
```

A guest's history lives in `sessionStorage`: it survives reloads and navigation within the tab and is gone when the tab is closed, so the next person using the browser never sees it. Each tab is its own guest session, so a product opened in a new tab starts a fresh conversation. Signing in carries the current tab's conversation into the shopper's history. `clearPersistedConversations` without `userId` deletes the guest history of the current tab.

## How it works

<Markdown>
{`
| Aspect | Behaviour |
|--------|-----------|
| Storage | A signed-in shopper's chats live in \`localStorage\` under \`cio-asa:chat:v1:<apiKey>:<domain>:<userId>\`, so they follow them across pages and tabs of the same site and a login change on a shared browser starts a separate history. A guest's chats live in \`sessionStorage\` under \`cio-asa:chat:v1:<apiKey>:<domain>\` and end with the tab |
| What is stored | Messages, product results as received, and the agent's \`thread_id\`; the next message continues the same server-side conversation |
| When it saves | When the answer stream starts, when it completes (or fails), and as a settled snapshot on \`pagehide\`, on unmount, and on \`newThread\` / \`switchThread\` while an answer is still in flight. Never per streamed chunk |
| On load | The most recent thread is restored before anything renders, so there is no welcome-screen flash. \`isHydrating\` is \`true\` meanwhile |
| Retention | Threads idle for 7 days expire, matching how long the agent remembers a thread. Expired entries are dropped on read and removed on the next write |
| Interrupted answers | Leaving the page mid-answer saves the turn as settled: a partial answer is shown as complete, an empty one as an error. Each record carries the id of the tab that wrote it, so a reload of that tab settles its own interrupted answer at once even when \`pagehide\` did not fire. Only a different tab treats a fresh in-flight record as still streaming, for up to 60 seconds |
| Non-conversational domains | The agent returns no \`thread_id\`; the transcript is still kept under a client-side \`local-\` id, which is never sent to the agent |
`}
</Markdown>

Storage stays on the device. Another browser or device starts fresh, and so does the agent's own memory, which is scoped per browser as well.

Two tabs of a signed-in shopper on the same thread merge their turns instead of overwriting each other: writes go through a Web Lock, the merge is redone if another tab committed in between, and an older snapshot can add turns but never regresses a message a newer one already settled. In browsers without Web Locks (Safari before 15.4) the merge is best effort: two tabs writing in the very same instant can still lose the slower turn.

## Several conversations

Every conversation is kept until it expires. A history list is built outside `Chat`: read the list from `onThreadsChange`, and drive the chat with `newThread()`, `switchThread(threadId)` and `clearHistory()` on its ref. `inFlight` on a `ThreadSummary` tells you the latest answer of that thread is still streaming, possibly in another tab.
