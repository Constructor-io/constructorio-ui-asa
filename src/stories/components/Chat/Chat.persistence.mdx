# Persistent Chat

By default a conversation lives only in memory and is lost on page load. Enable `persistence` on `CioAsaProvider` and the transcript plus the agent's thread id are kept in the browser, so a shopper who navigates between product pages, reloads, or comes back later continues where they left off.

```jsx
<CioAsaProvider apiKey="YOUR_API_KEY" persistence>
  <Chat />
</CioAsaProvider>
```

## Public API

Everything below is optional and only active when `persistence` is set on the provider.

<Markdown>
{`
| Where | Name | What it does |
|-------|------|--------------|
| \`CioAsaProvider\` prop | \`persistence\` | \`true\` enables persistent chat with the built-in \`localStorage\` strategy |
| \`Chat\` prop | \`onThreadsChange(threads, activeThreadId)\` | Fires after the initial load and whenever the stored list or the active conversation changes, including changes made in another tab. Use it to render a history list outside \`Chat\` |
| \`Chat\` prop | \`initialThreadId\` | Restores that thread's stored transcript instead of the most recent one; falls back to seeding the thread id alone when nothing is stored |
| \`Chat\` ref | \`newThread()\` | Opens an empty conversation and keeps the current one in storage |
| \`Chat\` ref | \`switchThread(threadId)\` | Loads a stored conversation and continues it on the same agent thread |
| \`Chat\` ref | \`clearHistory()\` | Resets the conversation and deletes it from storage |
| \`useAsaResults\` | \`isHydrating\` | \`true\` while a stored conversation is being restored |
| \`useAsaResults\` | \`threads\`, \`activeThreadId\` | Stored conversations, most recent first, and the id of the one on screen (\`null\` for an unsaved one) |
| \`useAsaResults\` | \`newThread()\`, \`switchThread(threadId)\` | Same as the \`Chat\` ref methods, for custom UIs |
`}
</Markdown>

`ThreadSummary` carries `threadId`, `title` (the first question), `createdAt`, `updatedAt` and `inFlight`, which is `true` while the latest answer of that thread is still streaming.

## How it works

`true` selects the library's default strategy. Today that is `localStorage`; a future release can move it to a server-backed store without changes on your side.

<Markdown>
{`
| Aspect | Behaviour |
|--------|-----------|
| Storage key | \`cio-asa:chat:v1:<apiKey>:<domain>\`, plus the client's \`userId\` when one is configured, so one shopper's chats follow them across pages of the same site and a login change on a shared browser starts a separate history |
| What is stored | Messages, product results as received, and the agent's \`thread_id\`; the next message continues the same server-side conversation |
| When it saves | When the answer stream starts, when it completes (or fails), and on \`pagehide\` while streaming. Never per streamed chunk |
| On load | The most recent thread is restored before anything renders, so there is no welcome-screen flash. \`isHydrating\` is \`true\` meanwhile |
| Retention | Threads idle for 7 days expire, matching how long the agent remembers a thread. Expired entries are dropped on read and removed on the next write |
| Interrupted answers | A reload mid-answer keeps the question. A partial answer is shown as complete, an empty one as an error |
| Non-conversational domains | The agent returns no \`thread_id\`; the transcript is still kept under a client-side \`local-\` id, which is never sent to the agent |
`}
</Markdown>

Storage stays on the device. Another browser or device starts fresh, and so does the agent's own memory, which is scoped per browser as well.

## Several conversations

Every conversation is kept until it expires. A history list is built outside `Chat`: read the list from `onThreadsChange`, and drive the chat with `newThread()`, `switchThread(threadId)` and `clearHistory()` on its ref. `inFlight` on a `ThreadSummary` tells you the latest answer of that thread is still streaming, possibly in another tab.
